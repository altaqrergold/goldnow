# GoldNow multilingual template review — branch new

Review source: user-provided `222.zip` (30 archive entries; 29 PHP files plus `style.css`). This report is based on static inspection of the archive, not a live WordPress render.

## Scope reviewed
- English reference: `taxonomy-countries-en.php`
- Target templates: `taxonomy-countries-id.php`, `-vi.php`, `-ko.php`, `-th.php`, `-ja.php`
- Shared theme files: `functions.php`, `goldnow-all-countries-15-langs.php`
- Other country templates were inventoried to compare architecture.

## Findings

1. The five target templates are a distinct implementation family. Their template headers say `(Rebuild)`; each has 1,399 lines, a standalone language header, a language-specific output-buffer callback, and a shortcode HTML translator. The English template is labeled `(SEO Test)`, has 1,221 lines, and does not use the same output-buffer layer. The other language templates have different line counts and architectures. This is structural divergence, not simply five translations of the English file.

2. The five target templates share the same 10 view keys: `24k`, `22k`, `21k`, `18k`, `14k`, `ounce`, `coin`, `gold-bars`, `gold-index`, and `usd`. The main calculation and view structure appears parallel in the five files. Static inspection does not prove runtime calculation equivalence.

3. Each target file has about 202 English-to-localized text mappings (Thai has 205). Their key sets are effectively identical; Thai has three additional keys. This is a partial text dictionary, not complete localization coverage.

4. Country names are localized inline for only 21 country codes in each target file. For other countries, `display_country_name` falls back to the English `country_english_name` metadata, then the URL slug, then `Country`. Therefore many country pages can show English country names by design.

5. Currency labels are localized inline for only 19 currency codes in each target file. For other codes, `currency_label` falls back to the English `$currency_labels_en` dictionary (or the raw code). This is a direct source of English currency names on countries whose currency is outside the 19-entry local list.

6. The shortcode translation pipeline first converts legacy Arabic labels into English using `$shortcode_translation_map`, then relies on the final output-buffer dictionary to convert those English strings into the target language. Any English label absent from that dictionary remains English. The global `$currency_names` and `$carat_labels` in `functions.php` are Arabic dictionaries, so this two-stage conversion is especially important.

7. Both HTML translation callbacks deliberately protect complete `<script>` and `<style>` blocks. The output-buffer callback translates text nodes and only these visible/accessibility attributes: `alt`, `title`, `aria-label`, and `placeholder`. It does not translate text embedded in JavaScript, nor arbitrary `value` or `data-*` attributes. The target templates contain English chart loading/error strings in JavaScript (for example, “Loading gold charts...” and “The chart data could not be loaded. Please try again.”). These can remain visible in English.

8. The target files contain a shortcode mapping for “Gold Ounce in Local Currency”. This is a point to verify against the intended product rule that the global ounce should be shown in USD only; static code inspection alone cannot confirm whether the shortcode actually renders that card in the live page.

9. The shared `goldnow-all-countries-15-langs.php` is a separate 15-language directory template. It uses a language table and PHP Intl country-region localization where available, with translation-helper/English fallbacks. It is not the same localization mechanism used by the five country templates.

10. PHP syntax check: all 29 PHP files in the archive passed `php -l`. This confirms syntax only; it does not validate WordPress hooks, shortcode output, browser rendering, SEO output, route resolution, or price calculations.

## Likely reasons English appears

- Only a subset of country names and currency names is translated inline.
- The English-to-localized map is finite and cannot cover every string generated by the theme and plugin.
- The shortcode layer intentionally normalizes Arabic labels to English before the second translation pass; missing second-pass entries leak through.
- JavaScript and CSS blocks are excluded from both HTML text-node translation passes, so chart/indicator UI strings can stay English.
- Attributes other than the explicitly listed accessibility attributes are not translated.
- Dynamic plugin/API data can arrive in English independently of the template's static dictionary.

## Recommended work plan

1. Freeze the archive as the baseline and do not edit the other ten language versions.
2. Use the English template as the structural/functional reference, while preserving the five Rebuild templates' intended language-specific SEO text and country routes.
3. Build a complete localization inventory per target language: visible HTML, headings/tabs/buttons, shortcode output, country names, currency names, karat labels, chart/indicator text, accessibility attributes, SEO title/description, and dynamic fallbacks.
4. Replace the Arabic → English → local two-stage label conversion with one explicit target-language dictionary for shortcode output, or a single localization function that returns target-language strings directly.
5. Expand country and currency localization to the complete country/currency dataset; do not use English as a visible fallback except for brand names, currency codes, and intentionally international notation.
6. Translate JavaScript-visible strings using language dictionaries passed safely into scripts; keep URLs, selectors, IDs, API keys, and calculation variables unchanged.
7. Verify the ounce rule and the 8-gram coin calculation against the live shortcode/plugin output before changing any calculation.
8. Make changes only to `id`, `vi`, `ko`, `th`, and `ja`; run PHP lint, route checks, tab-by-tab rendered-page checks, and price comparisons before calling the work complete.

## Change status
No theme PHP or CSS was modified during this review. The branch contains the review-scope README and this report. The source ZIP was inspected from the conversation attachment; the ZIP itself has not been committed to GitHub.
